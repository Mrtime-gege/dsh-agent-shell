# 面板重构方案 v2（全新设计，不保留旧取舍）

> 目标：**简单易用但不失深度**。所有参数摆到用户脸上；少部分维护类参数进二级菜单。
> 全部只消费 DSH 宿主令牌（`--dsw-alias-*` / `--dsw-font-*` / `--dsw-elevation-*`），零自创色值。

## 0. 设计原则

1. **参数就是界面**：任何"多少钱、什么状态、怎么关"都要一眼可见，不靠 hover/菜单猜。
2. **两级深度**：一级 = 摆脸上（标签条 + 状态条）；二级 = 抽屉（设置/历史/审计/诊断）。
3. **一个动作一条路**：访问设置只有"状态条 Ξ"一个入口；会话操作只有"tab ⋯ 菜单"一个入口。
4. **状态三色**：idle=state-success / busy=state-warn / 异常·锁定=state-error。
5. **诊断即是产品**：诊断抽屉含 control 原始回复查看器 —— 顺带把"嵌套 tmux 前台读数"的剩余疑点变成可随时实锤的产品能力（不再需要 DDEBUG 重启）。

## 2. 参数映射：脸上 vs 二级

### 摆脸上（一级，零点击可见）
| 参数/状态 | 载体 |
|---|---|
| 会话数 / 忙碌数 / 锁状态 | 胶囊（收起态） |
| 每个会话：label（主）、id（小字副标）、状态点（● idle / ○ busy / ✕ 异常） | 标签条 tab |
| 前台命令 fg / 空闲 | 状态条第 1 段（● 点色 + fg） |
| 几何 cols×rows | 状态条 ◻ 段（点击进 resize 步进器） |
| 滚存行数（historySize/limit） | 状态条 ▤ 段 |
| 归属（owner / 面板 / unknown） | 状态条 👤 段 |
| 守卫开/关 + 脱敏生效 | 状态条 🛡 段（点击看最近裁决 ⚠ 列表） |
| 审计开/关、留痕开/关 | 状态条 📼 段 |
| 键盘锁 / 推送 / 历史 / 设置 / 诊断 入口 | 状态条右侧工具钮（🔒 ⤒ 🕘 Ξ ⓘ） |

| 参数/操作 | 位置 |

## 4. 交互约定（深度来自"每段都可下钻"）

- 标签：点=切换；‥=会话菜单；×=关闭；label 文字点两下=内联改名（只改 label，id 始终可见副标）。
- 状态条每段：hover tooltip 说明；🔒 段点击=锁定/解锁；⤒=推送残留文本（原逻辑保留）；🕘=历史抽屉；📼=审计抽屉；Ξ=设置抽屉；ⓘ=诊断抽屉。
- 几何段点击 → resize 步进器（± 1/10，或输入数值，夹上下限）。
- 中断：Ctrl-C 保持"发送到前台"；标签 + 号新建（默认 label 自增、id 唯一）。
- 键盘：` 折叠/展开；Tab 在标签间切换；方向键进历史滚动（现有）。

## 5. 弃用的旧实现（"不合理不便捷"的位置）

- 旧"列表即面板"的文本行列表 → 标签条（id/label 双行可读）；
- 设置只存在于 DSH 设置页 → 面板内设置抽屉（同 schema 表单，就地生效提示）；
- 审计/诊断藏在模态弹窗 → 抽屉页可翻滚可筛选；
- 状态点只能靠颜色 → 段文字直接写明（fg/几何/历史/归属），颜色只是冗余强调；
- 没有 id 展示 → 每个 tab 常驻 id 副标（待办落地）；
- 无"原始回复诊断" → 诊断抽屉的 control 查看器（顺带定格 tmux 疑点）。

## 6. 实现阶段

- P1 基础：Capsule + TabBar + ScreenView 骨架（局部状态，先接 /list 与 /screen）—— UI 可见可点；
- P2 状态条 + 三色 + tooltip + resize 步进 + 抽屉壳（设置/历史/审计/诊断四页路由）；
- P3 交互深钻：label 内联改名、⋯ 会话菜单、guard 裁决列表、control 原始回复查看器；
- P4 令牌对所有样式收口 + 键盘 + 悬停工具条 + 键盘可达性 + 测试（纯函数拆出：状态条分段组装、参数分组、抽屉路由）。

## 7. 测试
