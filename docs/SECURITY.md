# 安全政策

> **本插件由 AI 开发、未经人工安全审计。** 本文件是作者自述的安全模型，不是独立评估结论；
> 请把它当作「作者认为的边界」，而不是「已经验证过的保证」。

## 开箱即用的依赖前提

装一个插件"装成功"不等于"能用"，这里把前提写清楚，缺什么插件会自己说：

| 依赖 | 谁提供 | 缺了会怎样 |
|---|---|---|
| `tmux` ≥ 3.x | **操作系统**（包管理器不会提醒） | 启动时体检发现 → 控制台 / `shell_diagnose` / `shell_open` / 面板 ⓘ 给出安装指引（Windows 需在 WSL 内运行） |
| `@deepseek-ai/{cordis,dsh-tools,schemastery}`、`react` | **DSH 运行时**（模块代理按 `dependencies + peerDependencies` 的**名字**转发到运行时自己那份） | 已声明为 **optional peer**：包管理器不会去装（否则会塞进第二份 cordis，服务/加载器不匹配），DSH 的代理机制照旧生效 |
| 权限预设 `danger-full-access` | 部署配置 | 受限模式下建会话报 `error connecting to /tmp/tmux-…`，面板与 `shell_diagnose` 会标出策略 |

一条命令自检全部前提：`./install-deps.sh --check`（只读，退出码 0 = 齐备）。

## 报告漏洞

请**不要**用公开 issue 披露尚未修复的安全问题。

首选渠道：本仓库 GitHub 的 **Security** 标签页 → **Report a vulnerability**（Private vulnerability
reporting）。该通道只对维护者可见，便于我们先修复再公开。

如果私有报告未启用，可以开一个 issue，但**只描述影响范围与复现所需的最小信息**，不要贴任何
可直接利用的载荷、凭据、内网地址或完整日志。我们会在私有渠道建立后请你补充细节。

反馈时请一并给出：DSH 版本、`tmux -V`、插件版本、以及你判断受影响的具体端点或工具。

维护者会尽快确认并给出处理计划。修复发布后会在 `CHANGELOG.md` 里注明。

## 支持范围

本项目处于 pre-1.0：只有**最新发布版本**会收到安全修复，不维护历史版本分支。

## 安全模型 —— 部署前请先读这一段

这个插件的设计目标就是「让人和 AI 像人一样操作一台真终端」。因此它的**能力边界等于本机 shell
权限**，下面每一条都是有意为之的设计，不是待修的缺陷。请据此判断它是否适合你的环境。

### 1. HTTP 端点没有独立鉴权 —— 现在有「浏览器面闸门」，但仍不是鉴权

面板与宿主半通过 HTTP 通信，端点在 `127.0.0.1` 上由 DSH 的 `webServer` 提供
（默认前缀 `/plugins/shell`，含 `/list`、`/screen`、`/keys`、`/new`、`/kill`、`/resize`、`/rename`、
`/diagnose`）。这些路由**不校验任何独立凭据**。

**这一条曾是最严重的漏洞，现已按威胁模型逐条收口**（每条检查都对应一条真实可达的攻击路径）：

| 攻击路径 | 修复前 | 现在 |
|---|---|---|
| **跨站请求伪造**：你访问的任意网页 `fetch('http://127.0.0.1:3080/plugins/shell/keys', …)` 往你的 shell 灌命令 | 可以打通 —— 请求体解析**不看 Content-Type**，而跨站「简单请求」不触发预检，响应读不到但命令已经执行 | 拒绝 `Sec-Fetch-Site: cross-site`；带 `Origin` 时必须与 `Host` 同源；**写请求必须是 `application/json`**（这一条会强制预检，而本插件不返回任何 CORS 头，浏览器发不出去） |
| **DNS rebinding**：攻击者域名解析到 127.0.0.1，浏览器视为同源 → 可读终端内容、也能写 | 可以打通 | `Host` 必须是回环地址，且端口必须等于实际监听端口 |
| **本机其它进程/用户**：同机任意进程都能连 127.0.0.1 驱动你的 shell | 可以打通 | 只有部署挂了 DSH 的 `connection` 服务时才能收口（它校验浏览器会话 cookie，返回 401）；本插件自身无法区分「你的浏览器」和「本机别的程序」—— **这一条属于接受的风险，见下** |

闸门在**路由注册处统一包裹**（不是每个 handler 自己检查），所以以后新增路由不会漏。
被拒的请求会记进面板 ⓘ 的「浏览器面闸门」一行与 `shell_diagnose`，便于现场排查。

**仍然成立的部分**：这不是鉴权。任何能通过上述检查的请求（例如本机进程伪造 `Host: 127.0.0.1:3080`
并带 `Content-Type: application/json`）依旧可以驱动 shell —— 端点本身就是「等价于本机 shell 权限」。

因此：**不要把 DSH Web 端口暴露到不可信网络。** 需要远程访问时用 SSH 隧道，或放在带鉴权的
反向代理之后，并自行确认代理没有把这些路径放进免鉴权白名单。如果只想收敛暴露面，可以把
`exposeHttp` 设为 `false`（面板会失去工作能力，仅保留模型工具）。

服务绑在 `0.0.0.0`（有意对外服务）时，`Host` 无法用于判定是否本机，闸门会**降级**并在面板上
以 `⚠` 明确标出「Host 围栏不可用」—— 那条路径上 DNS rebinding 未被挡住。

### 1.5 三层防线：授权门 / 浏览器面闸门 / 审计

本插件的定位是"让 AI 像人一样操作真终端"，所以它**不试图**把任意命令执行变成安全操作。
它能做的是让"谁能发起、能到达哪里、事后能不能查清"三件事都不含糊：

| 层 | 挡什么 | 挡不住什么 |
|---|---|---|
| **授权门**（`requireConsent`，默认开） | AI **在你不知情时**开始用这套 shell：一个对话第一次使用前必须由你手动确认，同意即授权该对话执行任意命令 | 你确认之后的一切 —— 那是授权的内容，不是漏洞。子代理继承已有授权（它没有人可以问）；关掉配置项即放弃此层 |
| **浏览器面闸门** | 跨站请求伪造、DNS rebinding 等"别人借你的浏览器"的路径（见第 1 条） | 本机其它进程；真正的鉴权仍需 DSH 的会话服务 |
| **审计**（输入流水 + 输出留痕） | "事后查不清"：谁、何时、对哪个 shell、发了什么、护栏是否拦下，全部落盘，会话关闭后留痕仍在 | 防抵赖（本机文件可改，见 8.5） |

要说清的一点：**授权门不是沙箱**。它只在"第一次"拦一下，把"AI 从此可以执行任意命令"这件事
变成一次显式的、有记录的人类决定；确认之后没有逐条审批（本插件无法接入官方审批，见 2.5）。

### 2. 高危命令拦截是启发式减速带，不是沙箱

`guardDangerousCommands` 用 20 条正则匹配危险形态，分成三组：

* **通用破坏**（10 条）：`rm` 根/家目录/通配、`--no-preserve-root`、`mkfs`、`dd of=/dev/`、
  覆盖块设备、fork bomb、`chmod 777 /`、`sudo`/`doas`/`su`、关机重启、`curl | sh`。
* **插件自身的命门**（8 条）：`tmux kill-server` / `kill-session`、`pkill|killall tmux`、
  `pkill|killall node`（宿主进程本身）、删除或覆盖 `~/.dsh/agent-shell`（审计与授权就在里面）、
  用 `find -delete` 删状态目录、`rm -rf ~/.dsh`。**这一组此前完全没有保护** —— 一个
  `tmux kill-server` 就足以把 AI 与用户的所有 shell 一起端掉。
* **发布纪律**（2 条）：`npm publish|unpublish|dist-tag|owner|token`、`git push` 带
  `--force|--mirror|--all|--tags`（不带 `backup` 远端时）。发版是维护者的决定，不该由 AI 代跑；
  往公开仓库推旧标签还可能把已撤销的版本重新发布。

它**可以被绕过**（字符串拼接、变量、写成脚本文件后执行、base64 等等），也**会误报**（正文里
出现 `sudo` 的普通文本同样被拦）。它的作用只是让「AI 手滑」变成一次显式确认，不是安全边界。
放行方式仍然是 `confirm: true`（面向人的显式确认）。

真正的隔离只能靠 DSH 的沙箱模式与操作系统权限。

### 2.5 没有接入官方审批，而且在这个模式下也接不进来

DSH 官方审批是 `@deepseek-ai/dsh-user-approval`（`ctx.approval`）＋ 工具管线的
`tools/pre-execute` waterfall。**本插件没有接入**，因此模型执行任何命令都不会弹出
「允许 / 拒绝」的询问。

这不是疏漏，而是平台设计上的互斥：官方权限预设把 `danger-full-access` 的审批策略定为
`never`（确定性拒绝，不弹 UI），而本插件**必须** `danger-full-access` 才能工作
（见下一条）。换言之，在本插件唯一可用的模式里，官方审批是被整体关闭的。

面板会在状态行如实标出 `审批 never`。要真正获得逐条审批，需要一个**能在受限沙箱里工作**
的终端方案，而不是本插件。

### 3. 本插件要求 `danger-full-access`

在 `workspace-write` 模式下创建 shell 会失败（`error connecting to /tmp/tmux-1000/...`），因为沙箱
挡住了 tmux 服务端。也就是说，装上本插件等于让该会话中的命令不再受文件沙箱限制。

如果你需要「有沙箱」的会话，请不要在这个会话里挂载本插件。

### 4. 输入与输出以明文留在会话里

所有键入的字符与终端输出都由 tmux 持有，并且 `shell_history` / `GET /screen` 会把它们**原样**
交回模型。这包括你在 shell 里敲的任何密码（`sudo`、`ssh`、`mysql -p` …）。

因此：不要在受管 shell 里输入长期凭据。确实需要时，用完立刻 `shell_close` 关掉该会话；
`history-limit` 调小只能减少囤积，不能改变「当前屏可被随时读走」这一事实。

### 5. 会留下一个脱离进程组的看门狗

宿主被强杀（例如 `kill -9`）时，tmux 服务端已经被 `setsid` 脱离，进程组的正常清理覆盖不到它，
所以插件会另起一个 `setsid` 守护脚本，等宿主消失后清理该 socket 上的 tmux。它的 pid 写在
`pidFile`（默认 `/tmp/dsh-agent-watchdog.pid`，内容为 `<看门狗pid> <被监视的宿主pid>`），
服务端配置文件写在 `/tmp/<socket>-tmux.conf`。

这两个临时文件是**其它本机用户可读的**（权限随你的 umask）。它们不含凭据，但会暴露「有人在跑
这个插件」以及宿主 pid。可以用 `watchdog: false` 关掉看门狗，代价是宿主被强杀后 tmux 会残留。

### 6. 默认只碰自己的私有 socket

插件使用私有 tmux socket（默认 `-L dsh-agent`），**不会**读取或干扰你日常使用的默认 tmux 会话。
但如果你把它指向默认 socket（`-L default` 或去掉 `-L`），它就会和你自己的 tmux 会话共享同一视图，
并能对它们收发按键 —— 那等于把上面第 1、4 条的影响扩大到你的全部终端。除非你明确想要这样，
否则保持私有 socket。

### 7. 本插件看不到的边界

它**不是**权限提升工具：管不到宿主进程能做的事之外的东西，也不会绕过操作系统权限。以哪个用户
运行 DSH，shell 就是那个用户；`sudo` 之后的权限变化完全由系统的 `sudo` 策略决定，插件只是把你
敲的密码原样转发进去。

### 8. 攻击面清单（一次彻底的过一遍）

把「谁能碰到什么」列清楚，比笼统说「权限很大」有用：

| 入口 | 谁能到达 | 能做什么 | 现在的闸门 |
|---|---|---|---|
| **9 个 `shell_*` 工具** | 只有被授权的模型（进程内调用，不经网络） | 等于当前用户的 shell | 高危命令启发式护栏；**没有**官方审批（见 2.5） |
| **HTTP 路由** | 本机任意进程；本机浏览器里打开的任何网页（CSRF/DNS rebinding） | 发按键（= 执行命令）、读屏幕、建/杀 shell | 浏览器面闸门（Host + 跨站 + JSON，见 1） |
| **`web_fetch` / 搜索等抓取到的内容** → 模型 → 工具 | 互联网上的任意页面 | 通过**提示注入**诱导模型执行命令 | 护栏只能挡明显形态；根本上取决于你是否让 AI 处理不可信内容 |
| **配置文件 / 设置页** | 能改你配置的人 | 改 `shell`、`socket` 等；`socket` 会被派生成路径并拼进 shell 命令 | `socket` 已收敛到 `[A-Za-z0-9._-]`；所有 shell 插值已加引号（见 9） |
| **面板本身** | 本机浏览器 | 与 HTTP 路由相同 | 同上 |
| **tmux 服务端 / 看门狗进程** | 同机用户可见其存在（临时文件、进程） | 无凭据；但可看到「有人跑着这个插件」 | 见 5 |

### 8.5 审计与留痕本身会落盘敏感内容

为了让"谁在什么时候让 shell 干了什么"可查，插件默认开启两层记录：**输入流水**
（`audit-YYYY-MM-DD.jsonl`）与**输出留痕**（`output/<shell>-*.log`，原样字节流）。
两者都在 `${DSH_HOME:-~/.dsh}/agent-shell/`，目录 0700、文件 0600。

代价必须说清：

* **留痕会把终端里出现过的敏感内容一起写下来** —— 包括你 `sudo` 时敲的密码回显、`export` 的令牌、
  程序打印的密钥。不需要长期留痕就 `captureOutput: false`；需要就 `auditDir` 指到加密卷。
* **它不是防抵赖的**：能读你 home 的进程就能改这些文件。它解决的是"事后查得清"，不是"证明没被改过"。
* 面板侧的人类输入只能记到 `panel` 粒度（浏览器里区分不到人）。

### 8.7 泄露排查（2026-09 一次完整的取证）

对四个面各扫了一遍：**仓库**、**git 历史**、**已发布的 npm 产物**、**运行时产物与本地文件权限**。

| 面 | 结果 |
|---|---|
| 仓库全文（含 docs 与脚本） | ✓ 无密钥/令牌/私钥；提交者是 GitHub noreply 邮箱 |
| 已发布产物（0.1.0–0.1.4） | ⚠ 见下：`PUBLISHING.md` 里带开发机绝对路径（**已发布的版本改不了**） |
| git 历史 | ⚠ 同样的路径字符串留在旧提交里（非密钥） |
| 插件运行时 | ✓ 不读任何凭据（只读 `DSH_HOME` 与 `DSH_PERMISSION_MODE`）；审计目录 0700、文件 0600 |
| 本地文件权限 | ⚠ → 已收紧：tmux 临时文件与留痕文件改为 `umask 077`（644 → 600） |

**已修的**：

- 仓库里那处开发机路径（测试文件里的写死路径）已改为占位符；
- `release:check` 的泄露扫描此前只覆盖 `lib/*` 与 `package.json`，**因此漏掉了会被发布的 docs** ——
  现在改为扫描**整个仓库的文本文件**，并新增主机名（`DESKTOP-*`）与 `sk-`/`AKIA` 形态；占位符
  （`/home/u`、`/home/user`）有白名单不误报。这条已用"把历史泄露塞回去"的方式验证过它真会失败；
- 生成的 shell 片段统一加 `umask 077`：`/tmp/<socket>-tmux.conf`、看门狗 pid 文件、以及 `pipe-pane`
  写出的**终端留痕文件**（后者可能含密码/令牌，最不该对同机其他用户可读）。

**留给你决定的**：

- 已发布版本里的那条路径字符串**在 npm 上无法修改**（版本不可变）。真正的风险不是字符串本身，而是
  **该用户名若同时被用作口令**（例如 sudo）——那种情况下应当更换口令；否则它只是"用户名 + 目录名"。
- 本机 `dsh-web.log` 含**带 token 的启动 URL**，此前是 644（同机其他用户可读）→ 已 chmod 600；
  彻底一点可以在启动脚本里加 `umask 077`（属于 DSH 侧，不在本插件范围内）。

### 9. 配置值不会被拼成命令（`socket` 注入面）

`socket` 名会被派生成 `/tmp/<socket>-tmux.conf`、`/tmp/<socket>-watchdog.pid`，而这两个路径此前
是**无引号**拼进 `sh -c` 的（共 6 处）—— 一个名为 `dsh; rm -rf ~ #` 的 socket 就是命令注入。
两条防线都已就位：

1. **收敛**：`socket` 在配置解析处就被裁剪到 `[A-Za-z0-9._-]`（非法字符剔除，纯点号/空值退回
   `dsh-agent`），并在面板与 `shell_diagnose` 里**如实说明改写过**（静默改名会让人找不到自己的会话）。
2. **引用**：所有 shell 插值改为单引号转义（`shQuote`），即使上层校验被绕过也无法注入。

回归测试真的执行了一次带恶意 socket 名的 `sh -c`，并断言注入标记文件**没有**被创建。
