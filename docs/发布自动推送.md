# 发布自动推送配置：让 GitHub + npm 自动发布（Trusted Publisher / OIDC）

> 适用：`dsh-agent-shell` 仓库（`Mrtime-gege/dsh-agent-shell`）每个版本的自动发布。
> 一次配置，以后 `推一个 v* 标签` 即自动发 npm 并建 GitHub Release。

## 链路（先看懂再动手）

```
push 一个 v* 标签
  → GitHub 触发 .github/workflows/release.yml（on: push: tags）
  → 校验：tag 与 package.json 版本一致、语法、release:check、该版本是否已在 npm
  → 仓库没配 NPM_TOKEN → 自动改走 OIDC
  → npm publish --provenance --access public（换干净 userconfig，只用 GitHub 的 OIDC 身份）
  → npm 对照「受信发布者登记表」验证：仓库名 + 工作流文件名（+ environment，本工作流没有）
  → 通过即视为包主本人发布（OIDC 算第二因素，不需要 OTP）
```

## 前置确认

- npm 账号是 `dsh-agent-shell` 的 owner（有 publish 权限）
- 能登录 `https://www.npmjs.com`（在自有物理机浏览器里即可，不需要 CLI 登录）
- 仓库公开：`Mrtime-gege/dsh-agent-shell`
- 工作流文件名 **`release.yml`**（**不能改**；npm 侧只填文件名、别带目录）
- 工作流**没有 `environment:`** —— npm 侧对应字段**必须留空**

## 一、npm 网页登记 Trusted Publisher（核心）

1. 打开 https://www.npmjs.com 并登录（有该包所有权的账号）
2. 进入包页：https://www.npmjs.com/package/dsh-agent-shell
3. 头像 → Packages → 选中 `dsh-agent-shell` → 包管理设置
4. Settings → **Trusted Publishing**（或 "Connecting to a third-party"）→ **Create new publisher / Add publisher**
5. 字段（照抄）：

   | 字段 | 值 |
   |---|---|
   | GitHub repository | `Mrtime-gege/dsh-agent-shell` |
   | Workflow | **`release.yml`（只填文件名，勿带目录）** |
   | Environment | **留空** |

6. **Allowed actions** 勾选"可以直接发布"（stage publish 恒允许，但普通 `npm publish` 需要直接发布权限）
7. 保存，出现一条 publisher 记录即完成

## 二、重推 tag 触发补发

Tag 已存在时**再 push 不触发**（工作流只在 tag 被 push/更新时跑）：

```bash
# 方式一（最稳）：删远端 tag 再推
git push origin :refs/tags/v0.1.6
git push origin v0.1.6

# 方式二：force 推同一 tag（ref 更新同样触发）
git push origin v0.1.6 --force
```

到 Actions 页观察新一轮 Release 运行：
- ✅ 绿色 = "发布到 npm（用 npm Trusted Publisher / OIDC）" 通过 → npm 出现该版本 → 自动建 Release
- 🔴 红色 = 打开该步骤日志，看第一行报错：
  - 403 invalid bearer / claims mismatch → repository 或 workflow 名写错、或 environment 填了
  - 404 trusted publishing not enabled → 登记的账号邮箱/包未进入该项
  - 401 permission denied → 该账号不是包 owner

## 三、验证

```bash
npm view dsh-agent-shell versions --json   # 应含对应版本
npm view dsh-agent-shell dist-tags --json   # latest 指向它
```

## 备选路线

- **NPM_TOKEN**：npm 网站 `Settings → Access Tokens → Generate → Publish` → 仓库 `Settings → Secrets and variables → Actions` 新增 secret 名 `NPM_TOKEN` → 重推 tag（工作流自动改走 token 路线）。
- **手工发布**：`cd dsh-agent-shell && git checkout v<版本> && npm publish --provenance --access public`
  （登录与 2FA/OTP 排查见 `PUBLISHING.md` §9，含 WebAuthn 通行密钥问题与 `npm-unpublish-webotp.py` 只读用法）
  成功后重推 tag —— 工作流"该版本是否已在 npm"检查会**跳过发布、只建 Release**。

## 幂等与重跑安全

- npm 不允许覆盖已发布版本；工作流发布前先查 registry：版本已在 → 跳过发布只建 Release。补发/重跑都安全。
- 信任配置唯一焊点：**Environment 留空 + 工作流文件名原样**，别乱加。
